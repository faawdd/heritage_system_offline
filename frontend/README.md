# Frontend (Vue3 + Vite)

## Stack

- Vue3
- Vite
- Pinia
- Vue Router
- Axios
- Element Plus
- ECharts
- OpenLayers

## Development

```bash
cd frontend
npm install
npm run dev
```

Default dev server: `http://localhost:5173`

API proxy target is configured to `http://127.0.0.1:8000`.

## Build

```bash
cd frontend
npm run build
```

Build output target: `../static/frontend`

## Notes

- This migration keeps legacy Django template pages online.
- New frontend pages are migrated module by module.
- Backend API namespace is `/api/v1/` for new pages.

## 四普导入与业务页面

- 四普导入的完整登记档案保存在 `ImmovableHeritage`，通过四普编号与
  `HeritageSite` 建立一对一关联。不可移动文物管理、文物一张图和 KML
  叠加检查使用后者；导入时会自动创建或更新对应文物点，不按名称合并。
- 不可移动文物管理中的“完整档案”按钮可查看和编辑关联登记表的全部字段。
  两个编辑入口保存的基础信息会同步，避免地图与完整档案不一致。
- “更新已有文物点边界”开关只影响已有文物点的边界更新，不影响档案进入
  业务页面；新文物点始终保存本次导入取得的边界。
- 升级已有部署时，先备份数据库，再在项目根目录执行
  `.venv/bin/python manage.py migrate`（其他环境使用对应的 Python 解释器）。
  `0038_heritagesite_registration` 会补齐此前已导入四普但未进入业务文物库的
  记录，保留已有文物点 ID 和非空边界，无需重新登录四普或重新下载附件。
  完成后重启服务并刷新页面。在线版和离线版都需要执行迁移。

## 地图定位与公文文号

- 项目关联已有 KML 记录时，初审回复前同时登记为初步选址材料，回复后
  用于正式选址。更换范围会清空对应阶段的旧核验结论，不覆盖已完成的初审回复。
  历史上已关联但未登记初步路径的收文项目可直接执行初步核查，无需重新上传；
  核查成功后补齐初步路径。缺失源文件仍会明确报错。
- 文物一张图、仪表盘及未选择 KML 的叠加地图按有效文物点分布居中并适配范围；
  无有效文物点时显示全国。空值、非有限值、越界坐标和导入时代表缺失的
  `(0, 0)` 不参与定位。数据异步返回后会重新计算范围。
- 选择 KML 或冲突对象后优先聚焦所选数据；详情地图显示当前文物点及全部
  本体、保护范围、建控地带区块。离线地图包预览按地图包覆盖范围定位。
- 项目详情的县局请示文号按当地实际文号输入，不再限制地区前缀、年份或
  编号格式；必填项、附件要求和最大长度仍保留。升级时执行数据库迁移
  `0039_alter_landuseprojectapproval_shanshan_request_num`。
- 定位回归测试：在前端目录执行 `node --test src/utils/mapViewport.test.js`。

## 弱网地图与 KML 上传

- KML 叠加页的地图工具和图例默认收起，通过右上角按钮展开；两面板互斥，
  可点击“收起”或按 Esc 关闭，图层开关与测距状态不因收起而重置。
  手机端面板限制为屏幕高度的 40% 并可滚动，文件管理菜单也默认收起。
- 文物点与 KML 读取使用 60 秒超时，仅对网络错误、超时和临时服务错误最多
  重试两次（间隔 1 秒、2 秒）。权限和参数错误不重试。
- 看板地图数据独立加载，不阻塞统计和图表；离开地图页面会取消文物点请求。
- KML 优先使用当前选择的内存缓存，每批最多 4 条、最多 2 批并发；
  成功批次立即显示，不等待其他文件。切换选择或离开页面会取消旧请求，
  未取消选择的已加载要素保持显示。缓存不写入本地持久存储。
- 批量请求网络失败不会再触发整批单条下载；旧服务不支持批量接口时仍兼容
  单条读取。图层加载失败后可点击地图工具栏的“重试加载”。
- 天地图瓦片每次加载最多等待 20 秒、最多重试两次，失败不阻塞业务叠加层；
  在线底图仍依赖外部天地图服务。离线版保留“地图源 → 离线地图”入口，
  已导入的本机切片仍走本地接口，不依赖天地图，也不套用在线瓦片重试逻辑。
- KML 上传、分析和导出请求允许等待 10 分钟，上传显示传输进度和服务端
  处理状态。写入操作不自动重试；未收到上传响应时，应先刷新记录确认
  是否已保存，再决定是否重新提交，避免重复上传。
- 部署需重新构建前端；如网关或应用服务器设置了更短的请求处理超时，
  还需按实际上传大小、带宽和分析耗时协调其超时、上传体积限制。
- 回归测试：前端目录执行 `node --test src/utils/*.test.js src/api/gisApi.test.js`。

## 项目空间核验（大文件）

项目管理中的“初步/正式选址核验”改为服务端后台任务：`POST /api/v1/projects/<id>/verify-spatial-safety/?async=1` 立即返回任务ID，前端轮询 `.../verify-spatial-safety/jobs/<job_id>/` 获取进度（解析/分析百分比）与结果。同一项目同类任务进行中时会复用，轮询偶发失败会自动继续，不再受单次请求超时影响。任务状态保存在系统临时目录（`heritage_spatial_jobs`），无需数据库迁移；不带 `async=1` 时仍为原同步行为。
