# 文物综合管理平台：项目文档整合

> 本文是 `master` 与 `offline2` 分支 Markdown 文档的统一入口。原有专项文档保留用于追溯，本文负责提供去重后的项目说明、部署流程、功能边界和文档索引。

## 1. 核对范围与结论

### 1.1 核对范围

本次核对以两个分支中已提交的 Markdown 文件为准：

- `master`：登录修复、迁移分析与实施记录、FastAPI 部署、前端说明。
- `offline2`：上述共同文档，以及 `docs/offline-desktop.md`。

两个分支共有 12 个同路径文档，`offline2` 额外包含 1 个离线桌面文档。差异集中在以下三个文件：

| 文档 | 差异 | 统一处理 |
| --- | --- | --- |
| `SERVER_LOGIN_FIX.md` | `master` 包含在线版验证码、账号锁定、IP 限速说明；`offline2` 版本删去了该段 | 本文保留为在线版安全策略，并单独说明离线版边界 |
| `fastapi_server/deploy/DEPLOY_PROD.md` | `master` 含登录防护部署提醒；`offline2` 版本更精简 | 本文将迁移、共享数据库、代理信任和网关部署要求合并 |
| `docs/offline-desktop.md` | 仅 `offline2` 存在 | 作为离线桌面版正式章节保留 |

### 1.2 统一原则

1. 原有报告、测试记录和故障指南不删除，避免丢失排障依据。
2. 重复内容以本文为准，专项文档只保留详细命令和历史背景。
3. 在线版与离线版的差异明确标注，不把一个分支的部署方式误用于另一个分支。
4. 历史实施记录视为状态记录；实际行为以当前代码、数据库迁移和发布配置为准。

## 2. 项目能力总览

平台由 Django 业务后台、Vue 前端和 FastAPI 移动端网关组成，并可通过 Electron 打包为离线桌面应用。

### 2.1 业务模块

- 文物档案、不可移动文物管理和文物一张图。
- 巡查记录、现场照片、定位和看护员工作台。
- 用地项目、审批流程、项目审计和报告导出。
- 四普完整登记档案导入，并按四普编号关联业务文物点。
- KML/KMZ、OVKML、DXF 转换，冲突分析，边界 CSV/KMZ 导出。
- 用户、用户组、权限、登录日志、操作日志和审计日志。

### 2.2 技术边界

| 部分 | 作用 |
| --- | --- |
| Django | 管理后台、业务模型、迁移、传统页面和部分 API |
| Vue/Vite | 新版地图、统计、GIS、项目等模块 |
| FastAPI | 移动端 `/app-api` 网关，与 Django 共享数据库 |
| Electron | 离线桌面壳和本地运行时 |
| SQLite | 开发环境及离线桌面默认数据库；生产环境应按实际配置确认数据库类型 |

## 3. 开发环境与启动

### 3.1 服务端

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Windows PowerShell：

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

### 3.2 前端

```bash
npm --prefix frontend ci
npm --prefix frontend run dev
npm --prefix frontend run build
```

前端使用 Vue 3、Vite、Pinia、Vue Router、Element Plus、ECharts 和 OpenLayers。新迁移页面使用 `/api/v1/` 命名空间，旧 Django 页面继续保留。

### 3.3 FastAPI 移动端网关

本地调试可直接运行：

```bash
uvicorn fastapi_server.main:app --host 127.0.0.1 --port 8000
```

生产部署时 FastAPI 通常监听 `127.0.0.1:8000`，再由既有 HTTPS Nginx 服务以 `/app-api` 反向代理。网关和 Django 必须连接同一个数据库，否则用户、权限、上传和巡查数据会出现不一致。

## 4. 部署与升级

### 4.1 FastAPI 移动端网关

服务器安装依赖并创建虚拟环境：

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip nginx
cd /opt/heritage_system
python3 -m venv .venv
source .venv/bin/activate
pip install -U pip
pip install -r fastapi_server/requirements.txt
```

本机验证：

```bash
/opt/heritage_system/.venv/bin/uvicorn \
  --app-dir /opt/heritage_system/fastapi_server main:app \
  --host 127.0.0.1 --port 8000
curl http://127.0.0.1:8000/
```

随后按 [`fastapi_server/deploy/DEPLOY_PROD.md`](../fastapi_server/deploy/DEPLOY_PROD.md) 配置 systemd 和 Nginx，并验证：

```bash
curl -k https://<域名>:<端口>/app-api/
```

不要将 Uvicorn 直接暴露到公网；`forwarded-allow-ips` 只填写实际可信反向代理地址，禁止使用 `*`。

### 4.2 Django 数据库升级

升级在线版或离线版前都应先备份数据库：

```bash
python manage.py migrate
python manage.py collectstatic --noinput
```

四普数据升级重点：

- 完整登记档案保存于 `ImmovableHeritage`。
- 业务文物点保存于 `HeritageSite`。
- 两者按四普编号建立一对一关联，不按名称合并。
- 更新已有文物点边界只影响已有点，新导入点仍会保存本次导入边界。
- 迁移后重启 Django、FastAPI 和前端静态资源服务，并刷新浏览器。

### 4.3 登录故障

数据库迁移后若旧用户缺少 `UserProfile`，按以下顺序处理：

1. 备份数据库并执行全部迁移。
2. 使用 `fix_login_issue.py` 或 Django shell 为已有用户补建 `UserProfile`。
3. 重启服务并检查服务日志。
4. 使用实际用户测试 Web 与 App 登录。

详细命令见 [`LOGIN_FIX_GUIDE.md`](../LOGIN_FIX_GUIDE.md)、[`SERVER_QUICK_FIX.md`](../SERVER_QUICK_FIX.md) 和 [`SERVER_LOGIN_FIX.md`](../SERVER_LOGIN_FIX.md)。

## 5. 登录安全与权限

### 5.1 在线版

- Web 登录需要图片验证码；验证码本机生成，有效期默认 120 秒，提交后即失效。
- 账号连续认证失败 5 次后默认锁定 900 秒；Web 与 App 共享锁定状态。
- 同一来源 IP 的登录请求默认每 60 秒最多 30 次，验证码获取另有独立限速。
- App 保留现有 `{username, password}` 登录格式，不强制验证码，但受账号锁定和 IP 限速保护。
- 登录成功、拒绝和相关操作写入登录或审计日志。
- 数据库防护表缺失或不可用时不得降级放行，应修复迁移或连接问题。

可在 `.env` 中调整策略，但 Django 与 FastAPI 必须使用同一组配置：

```dotenv
LOGIN_MAX_FAILURES=5
LOGIN_LOCK_SECONDS=900
LOGIN_IP_LIMIT=30
LOGIN_CAPTCHA_IP_LIMIT=30
LOGIN_IP_WINDOW_SECONDS=60
LOGIN_CAPTCHA_TTL_SECONDS=120
```

### 5.2 离线版

- 本地登录、数据库、媒体、日志和地图切片不依赖在线服务器。
- 首次启动只在没有活动超级管理员时创建 `admin` 账户；初始密码仅用于首次登录。
- 首次登录必须修改密码并设置 3 个不同的安全问题。
- 忘记密码需验证原有安全问题；连续输错密码或安全问题会触发冷却/锁定。
- 临时安全问题 JSON 含明文答案，必须限制权限、使用后立即删除，禁止提交仓库或写入 CI 日志。
- 天地图只在用户主动切换在线底图时联网；DEM 缺失不会自动联网下载。
- 四普导入和 DeepSeek 等外部集成仍需要网络或服务端点，不属于完全离线能力。

## 6. 离线桌面版

离线桌面版以在线版 Django 模型和迁移为业务基线，使用本机 SQLite。数据写入 Electron `userData` 目录，不写入安装目录。

### 6.1 构建

```bash
npm --prefix frontend ci
npm --prefix frontend run build
bash scripts/build_desktop_runtime.sh
cd frontend
npx electron-builder --publish never --linux AppImage deb rpm --x64
```

Windows 使用 `scripts/build_desktop_runtime.ps1`；Electron Builder 支持 Windows NSIS、macOS DMG/ZIP、Linux AppImage/DEB/RPM。发布工作流在推送 `v*` tag 时构建桌面产物。

### 6.2 离线地图

系统管理中的“离线地图切片”支持：

- QGIS 或兼容工具导出的 `.mbtiles` 栅格瓦片数据库；
- 按 `z/x/y.png`、`z/x/y.jpg` 或 `z/x/y.webp` 组织的 XYZ/TMS ZIP。

底图切换不会清除文物、KML 和保护区等业务叠加图层。

### 6.3 卸载与 macOS

Windows 卸载器和 Linux DEB/RPM 钩子可清理用户数据；macOS 与 AppImage 没有系统级卸载钩子，删除应用前需使用应用包内的 `uninstall-user-data.sh --confirm` 并输入 `DELETE`。清理不可撤销，升级不会触发清理。

当前 macOS 包未签名和公证。仅在确认 Release 来源可信后，按 [`docs/offline-desktop.md`](offline-desktop.md) 的说明处理 Gatekeeper 隔离属性。

## 7. 迁移状态

### Wave 1：文物管理

- 文物一张图、文物统计、文物详情页及边界导出已迁移到 `/api/v1/heritage`。
- 新前端页面与旧 Django 页面并存，数据库模型和旧接口保持兼容。

### Wave 2：GIS/KML

- KML 记录管理、批量冲突分析、冲突报告、边界导出和 OVKML 转换已接入 `/api/v1/gis`。
- 地图支持底图切换、KML/冲突图层显隐、测距和冲突明细双向联动。

### 项目模块

项目模块按页面逐步迁移；迁移遵循复用既有业务逻辑、保留旧入口、增加新 API 的原则。具体范围以 `docs/migration/` 中的实施记录和当前代码为准。
